# 版本安排
- 现在训练预测与伪标签已经告一个段落了，需要将现在的所有dataset/下面的数据进行人工labelstudio进行精细化标注；
- 该版本的目的是编写一个迭代功能：将dataset下面的所有有标签数据进行导入labelstudio进行标注的能力，生成的文件应该可以直接导入到labelstudio中进行细化标注；
- 输出到output/to_labelstudio文件夹下面，输出内容包括原始图像和导入labelstudio的导入文件格式；

# 版本分析

## 1. 版本定位

v10 的目标是将当前 `dataset/` 中已有标注的数据整理为可直接导入 Label Studio 的人工复核任务，为后续精细化标注建立可追溯的迭代入口。当前项目的标签是单类别 `tooth` 的 YOLO 检测框，格式为 `class x_center y_center width height`；因此本版本输出的是牙齿矩形框预标注，不是像素级分割标注，也不应将既有检测框表述为分割掩码。

该功能不训练新模型、不改变现有 YOLO 检测流程，也不自动产生 FDI 编号或氟斑牙分级。Label Studio 中的人工修订结果才是后续精细标注数据的来源。

## 2. 输入范围与去重原则

`dataset/images/train`、`dataset/images/val` 是由 `dataset/raw/` 生成的派生数据。直接遍历整个 `dataset/` 会将同一图像导出两次，因此导出器应以 `dataset/raw/` 中结构完整的 `images/`、`labels/`、`classes.txt` 数据源为准，或在导出前按源图哈希和文件名进行去重。

处理前必须校验每个源目录中图像与标签按 stem 一一对应、类别 ID 为 `0`、坐标已归一化且宽高为正。遇到重复文件名、重复 stem、缺失标签、无效坐标或损坏图像时，应报告具体文件并停止，不得静默覆盖或跳过后继续生成不完整任务集。

## 3. Label Studio 导出格式

输出目录固定为 `output/to_labelstudio/`，建议包含以下内容：

```text
output/to_labelstudio/
  images/                 # 导出的原始图像副本，按唯一任务 ID 命名
  tasks.json              # 可直接导入 Label Studio 的任务与预标注
  label_config.xml        # 对应的 Label Studio 标注界面配置
  manifest.json           # 图像、来源标签、哈希和导出时间的追溯清单
  README.md               # 导入、复核和导出说明
```

每个 `tasks.json` 任务应包含可访问的图像路径和由现有 YOLO 框转换的百分比坐标。预标注应采用 Label Studio 的 `RectangleLabels` 结构，并使用 `predictions` 字段作为待人工修订的建议，避免把未复核框直接记为完成的人工真值。`from_name`、`to_name` 和标签名称必须与 `label_config.xml` 完全一致。

当前可先使用单一 `tooth` 矩形标签完成框校正。若本阶段的“精细化标注”要求逐牙轮廓，则应在配置中使用 `PolygonLabels`，由标注人员重新绘制多边形；现有检测框只能作为定位参考，不能自动转换成真实轮廓。若后续需要 FDI 标注，应在 Label Studio 配置中显式提供 FDI 类别或独立牙位字段，并定义不可见牙、无法判读牙和缺失牙的标注规则。

## 4. 可追溯性与人工审核

`manifest.json` 应逐任务记录：唯一任务 ID、导出图像文件名、原始数据源、原始图像路径、源图 SHA-256、源标签路径、源标签 SHA-256、导出时间、导出工具版本和初始标签类型。人工审核后的 Label Studio 导出结果应保留原始任务 ID，并记录审核者、审核时间、审核状态和修改原因。

原始 `dataset/raw/` 视为输入快照，不应被导出命令修改。人工复核后的新标注应写入新的版本化目录，例如 `dataset/raw/manual-label-v10/`，并保留与原始候选的关联，而不是覆盖旧标签。只有完成审核并通过格式校验的数据才可进入后续训练集重建。

## 5. 实施流程

1. 校验 `dataset/raw/` 中各来源的图像、标签、类别定义和文件名唯一性。
2. 为每个待标注图像分配稳定且唯一的任务 ID，复制原图到 `output/to_labelstudio/images/`。
3. 将 YOLO 归一化框转换为 Label Studio 百分比坐标，生成 `tasks.json`、`label_config.xml` 和追溯清单。
4. 在 Label Studio 中导入标注配置和 `tasks.json`，人工修订检测框；如需要精细轮廓或 FDI，则按预先定义的规则补充标注。
5. 导出人工审核结果，执行图像/标签配对、类别、坐标、重复项和标注完整性校验。
6. 将审核通过的结果发布为新的人工标注数据版本，再使用明确的 seed、划分比例和 manifest 重建训练/验证集。

## 6. 验收标准与风险

验收时应确认：导出的图像数量与任务数量一致；每项预标注可在 Label Studio 中正确显示；任务图像路径在目标部署环境可访问；每个任务均能追溯到唯一源图和源标签；重复数据不会生成重复任务；导出过程不修改 `dataset/raw/`、现有训练输出或模型权重。

主要风险是把派生 train/val 数据与 raw 数据同时导出而造成重复标注、把模型或候选框误当成人工真值、以及在未定义 FDI/多边形标注规范前混合不同粒度的标签。v10 应先完成可复核、可追溯的 Label Studio 导入闭环；像素级分割、FDI 识别和氟斑牙分级应在获得相应人工标注后作为独立后续任务实现。
