## 1. 范围与前提

本轮只讨论 DINOv3 牙科预训练 / 微调与下游特征质量。

- 不再讨论 before/after 八模型检测实验；
- 检测 AP 口径、OMNI 检测 test 泄漏等问题延后；
- 下游只保留两个分类任务：氟斑牙 4 级（200 张）、口腔疾病 6 类（720 张）；
- 所有数字以 v1/v2 和当前 probe 输出为准，但**在干净数据重评前均为初步观察**。

当前事实基线：

- Stage 1 完成 16,080 步，5k/10k/15k/16k 四个 checkpoint 都已评估；
- 当前 224 CLS linear probe 上，四个 checkpoint 都低于 base；
- 5k 最差、15k 最好，训练越久越好但未追平 base；
- pair cosine 从 base 0.823/0.628 降到 5k 0.156/0.074；
- 疾病 720 有 643 唯一哈希、22 组跨类重复；氟斑牙 199/200；
- 两个分类集与 42,618 张预训练图哈希重叠为 0；
- 疾病集重复、统计口径、QWK 误用、符号问题需要先修。

## 2. 项目分析（D1）

### 2.1 DL / 自监督预训练专家（A）

**判断**：工程链路已经成型，但科学问题还没有被回答。

- 数据审计、去重、离线训练、checkpoint、probe 都能跑通；
- Stage 1 的 loss/梯度健康，说明优化本身没问题；
- 但“域内预训练提升下游”目前没有证据：四个 checkpoint 的 224 CLS probe 都低于 base；
- 更有价值的发现不是“loss 下降”，而是“5k 就出现特征漂移、后续训练只能部分恢复任务性能”——这是一个可研究的现象；
- 当前不能把“低于 base”解释成“域适配无效”，因为 probe 数据有重复、统计口径有问题、LoRA/全量/dense 都没做。

**A 的判断**：项目处于“工程成功、科学假设未验证”的阶段；应该先修正评估，再用 anti-drift 配方做 2–3 个受控实验。

### 2.2 牙科影像 / 氟斑牙专家（B）

**判断**：任务定义和样本单位比模型更值得先讨论。

- 氟斑牙分级是**有序、局部**的：normal/mild/moderate/severe 的边界依赖釉质白垩、褐色斑、表面纹理，整图 CLS 很容易被背景、器械、光照和其他牙齿稀释；
- 200 张、每类 50 张，虽然平衡，但对四级分级仍然偏小；需要患者级切分和临床复核；
- 口腔疾病 6 类不是互斥的：Calculus 与 Gingivitis 常共存，跨类重复可能反映共病，不一定只是“错标”；
- 如果坚持互斥单标签，应该排除共病样本或改多标签；否则同一张图两个真值，模型无法同时判对；
- “牙齿检测 → 单牙 ROI → 分级”在临床上更合理，但这属于论文 B 的架构创新，不应混进当前预训练论文。

**B 的判断**：当前整图 CLS 评估与临床任务单位不匹配；至少应增加 ROI/patch 级 probe，再谈“特征好不好”。

### 2.3 医学 AI 评估 / 统计专家（C）

**判断**：当前最关键的问题是评估可信度，不是模型容量。

- 疾病集跨类重复 + 普通 StratifiedKFold → 训练/验证泄漏；
- 25 折配对 t 检验不是独立实验，p 值不能作为正式结论；
- 六类疾病用 QWK 不合适，应改 macro-F1 / balanced accuracy；
- 原报告差值符号写反：`base − checkpoint` 实际是 `checkpoint − base`；
- frozen CLS 只是下界；LoRA/全量、patch/dense、512 都未评估；
- 在这些修完之前，Stage 1 的数字只能算 preliminary。

**C 的判断**：先做 G0（干净数据 + 正确指标），否则后面所有预训练实验都会在“不可信的尺子”上比较。

### 2.4 论文方法学 / 审稿专家（D）

**判断**：当前故事不足以支撑一篇方法论文。

- “我们在牙科数据上继续预训练 DINOv3”本身不够新；DinoDental、DOVE 等工作已经覆盖了“DINOv3 牙科适配”的大方向；
- 需要更锐利的贡献：anti-drift 配方、数据/评估协议、牙科专用 token/arch，三者选其一作为主线；
- 如果最终没有正向结果，可以写“严格评估/负结果”，但必须：
  - 数据干净、统计正确；
  - 有明确的失败机制分析；
  - 有可复现的协议和开源；
  - 不能把“我们训了但没超过 base”直接当论文卖点。

**D 的判断**：项目需要一个“故事决策”：正向方法、严格评估、还是应用落地；三者不能混着写。

### 2.5 共识（D1）

1. 工程基础成立；
2. 科学假设未验证；
3. 评估必须先修；
4. 当前最值得研究的是“漂移/anti-drift”，不是继续堆训练量；
5. 论文故事需要在 v3 讨论后定一个方向。

## 3. 当前架构的合理性（D2）

### 3.1 合理的部分

- **ViT-B/16 作为骨干是合理的**：86M、768 维、RoPE、4 storage tokens、dense patch 特征，适合后续检测/分割/分级；
- **师生 EMA + 多裁剪 + iBOT**：是 DINOv3 的标准自监督框架，能学局部/全局一致性；
- **224/96 主训练 + 512/128 适应**：方向合理，尤其考虑数据分辨率；
- **25GB 卡上用 batch 320、激活检查点**：工程上可行，吞吐也合理。

### 3.2 不合理 / 需要改的部分

1. **全参数 continue-pretraining 的风险被低估**
   - 官方 recipe 假设更大数据/更大 batch；42k 窄域数据上全参数继续训练，5k 就漂移；
   - P0 的灾难性退化是极端版，Stage 1 是温和版，但方向一致；
   - 需要 anti-drift（base 蒸馏/冻结 Gram/LoRA/部分冻结）。

2. **CLS-only 线性 probe 太窄**
   - 只能说明“全局 CLS 的线性可分性”，不能说明 patch/dense 特征；
   - iBOT/Gram 的价值更可能在局部/密集任务；
   - 应增加 patch-mean、ROI、kNN、MLP、dense 小实验。

3. **任务单位不匹配**
   - 预训练是整图，氟斑牙分级是局部/单牙；
   - 整图 CLS 可能依赖背景/器械；
   - 需要 ROI/patch 评估，或论文 B 的单牙 token。

4. **数据源与分辨率不匹配**
   - COde 87%、低分辨率；AlphaDent 只有 1.4k 高分辨率；
   - 97.3% 短边 <384；512 阶段大多是上采样；
   - 需要来源平衡、质量过滤、自适应 crop 比例。

5. **K/KoLeo/训练长度未校准**
   - K=32768、N=42,616，K/N≈0.77，记忆风险高；
   - KoLeo 0.05 仍在推远特征；
   - 120 epochs 后段平台，5k 就漂移；
   - 应降 K、降 KoLeo、短 schedule、early probe。

### 3.3 架构层面的候选改进

| 方案 | 做法 | 优点 | 风险 | 优先级 |
| --- | --- | --- | --- | --- |
| A. base 特征蒸馏 | student 对齐 frozen base 的 CLS+patch | 直接抑制漂移 | 可能限制域适应 | 高 |
| B. 冻结 Gram anchor | Gram teacher = base checkpoint | 保留 dense 结构 | 需改配置/数据管线 | 高 |
| C. LoRA / 部分冻结 SSL | 冻结 backbone，训练 LoRA+heads | 几乎不破坏 base | 容量小 | 中高 |
| D. 短 schedule + 低 K/KoLeo | 30–60 epochs，K=16384/8192 | 降低记忆/漂移 | 可能欠拟合 | 高 |
| E. 512 Stage 2 + Gram | 高分辨率适应 | 细粒度 | 数据上采样多 | 中 |
| F. 单牙 token / 牙间 Transformer | ROI→token→Transformer | 临床合理、创新性强 | 需要分割/牙位标注 | 低（论文 B） |

**共识（D2）**：骨干选型合理；训练目标和评估架构需要改；优先做 A/B/C/D，F 留到论文 B。

## 4. 论文撰写方案与故事线（D3）

### 4.1 三个候选故事

#### 故事 A：正向方法论文

**题目方向**：*Base-Anchored Domain Adaptation of DINOv3 for Intraoral Images*

- 贡献：不是“在牙科数据上继续预训练”，而是“如何在适应牙科域的同时不破坏 base 语义”；
- 方法：base 特征蒸馏 + 冻结 Gram anchor + 短 schedule + 数据平衡；
- 结果要求：在干净数据上，至少一个下游任务相对 base 有稳定正增益；
- 风险：如果 anti-drift 仍然不如 base，故事 A 不成立。

#### 故事 B：严格评估 / 负结果论文

**题目方向**：*When Does Dental Domain Pretraining Help? A Controlled Study of DINOv3 Adaptation*

- 贡献：数据审计、base vs adapted、frozen/LoRA/full、分辨率、来源偏置、失败机制；
- 结果要求：即使没有正向增益，也要有干净、可复现、有信息量的结论；
- 风险：审稿人可能认为“负结果不够新”；需要强协议和明确机制。

#### 故事 C：应用论文

**题目方向**：*OralDINO for Fluorosis Grading and Oral Disease Screening*

- 贡献：把 OralDINO 作为 backbone，做氟斑牙分级/口腔疾病筛查；
- 结果要求：临床相关数据 + 外部验证 + 可解释性；
- 风险：需要更多数据和临床合作；当前 200 张不够。

### 4.2 推荐策略

**先做 4 周“故事决策实验”**：

1. 第 1 周：干净数据重评（base + 5k/10k/15k/16k）；
2. 第 2 周：anti-drift 配方（蒸馏/冻结 Gram/低 K/低 KoLeo/短 schedule）2–3 个短实验；
3. 第 3 周：LoRA/全量 + patch/ROI probe；
4. 第 4 周：根据结果选故事：
   - 有稳定正增益 → 故事 A；
   - 没有但评估/机制扎实 → 故事 B；
   - 有临床合作/更多数据 → 故事 C（否则不做）。

### 4.3 论文 A 的推荐结构（若走故事 A/B）

1. **Introduction**
   - 口内图像域鸿沟、数据分散、标注稀缺；
   - 现有 DINOv3 牙科适配工作（DinoDental、DOVE）与空白；
   - 本文问题：域适配是否能在不破坏 base 的前提下提升下游？
2. **Related Work**
   - DINOv3 / 自监督；
   - 牙科基础模型；
   - 医学域适配与灾难性遗忘。
3. **Method**
   - 多源数据审计/去重/来源平衡；
   - base-anchored continue-pretraining（蒸馏/冻结 Gram/短 schedule）；
   - 小 batch softmax+center；
   - 评估协议（分组 CV、macro-F1/QWK、LoRA/全量）。
4. **Experiments**
   - 氟斑牙 4 级 + 口腔疾病 6 类；
   - base vs adapted；frozen/LoRA/full；
   - 分辨率/来源/数据消融；
   - patch/ROI/dense 小实验。
5. **Discussion**
   - 失败模式、漂移、数据偏置、适用边界。
6. **Conclusion**

### 4.4 论文写作的“不要”

- 不要写“显著提升”除非干净数据 + 置信区间支持；
- 不要用 200 张小数据声称 SOTA；
- 不要把训练 loss 下降当任务提升；
- 不要混用检测 AP 代理指标；
- 不要声称临床诊断效用。

## 5. 创新点的形成、合理性与可行性（D4）

### 5.1 候选创新点

| 编号 | 创新点 | 新颖性 | 可行性 | 风险 | 建议角色 |
| --- | --- | --- | --- | --- | --- |
| I1 | **Base-anchored dental DINOv3 adaptation**：特征蒸馏 + 冻结 Gram + 短 schedule，抑制灾难性遗忘 | 中高 | 高 | 中 | 论文 A 主线 |
| I2 | **Data-centric dental SSL protocol**：多源审计/去重、来源平衡、分辨率自适应 crop、干净分组评估 | 中 | 高 | 低 | 论文 A 支撑 |
| I3 | **Small-batch DINOv3 stabilization**：softmax+center、K/N 校准 | 中低 | 高 | 低 | 方法细节/消融 |
| I4 | **Dental token / arch modeling**：单牙 token + 牙间 Transformer + FDI/分级 | 高 | 中低 | 高 | 论文 B |
| I5 | **Dense/patch-level evaluation for dental SSL**：ROI/patch probe、病灶级评估 | 中 | 高 | 中 | 论文 A 支撑 |

### 5.2 为什么“在牙科数据上预训练 DINOv3”不够新

- DinoDental 已经系统评估了 DINOv3 在牙科任务上的 frozen/LoRA/full；
- DOVE 已经做了约 53 万口内照片的 DINOv3 ViT-B 域适配；
- 因此，“我们用 42k 牙科图继续预训练 DINOv3”本身很难作为主要创新；
- 需要差异化：
  - **I1**：anti-drift/保留 base 语义；
  - **I2**：数据审计、来源平衡、干净评估；
  - **I5**：dense/patch 评估；
  - **I4**：牙科专用 token/arch（但需要更多标注）。

### 5.3 推荐组合

**论文 A**：I1 + I2 + I5

- 主线：如何在牙科域适配中不破坏 base，并正确评估；
- I2/I5 是支撑，不是独立卖点；
- I3 作为实现细节/消融。

**论文 B**：I4

- 单牙 token + 牙间 Transformer + FDI/氟斑牙分级；
- 需要分割/牙位标注和更多数据；
- 不与论文 A 混写。

### 5.4 可行性评估

| 创新点 | 需要的资源 | 现有条件 | 结论 |
| --- | --- | --- | --- |
| I1 | 25GB GPU、5k–10k 步短训练、base 权重 | 已有 | 可行 |
| I2 | 数据审计、来源平衡、分组评估 | 已有数据 | 可行 |
| I3 | 配置改动 | 已有 | 可行 |
| I4 | 单牙分割/牙位标注、更多数据 | 不足 | 高风险，论文 B |
| I5 | patch/ROI 特征、probe 脚本 | 可扩展 | 可行 |

### 5.5 创新性判断

- **I1 是当前最合理的“方法创新”**：P0/Stage 1 的漂移现象为它提供了真实动机；如果 anti-drift 能把下游拉回/超过 base，故事成立；
- **I2/I5 是“评估/数据创新”**：单独不够，但能显著提高论文可信度；
- **I4 是“架构创新”**：创新性最高，但当前数据和标注不足以支撑，建议放到论文 B；
- **I3 是“工程创新”**：可以作为方法细节，不宜作为主创新。

## 6. 专家分歧与共识（D5）

### 分歧 1：现在做 I4（牙科 token）还是先做 I1（anti-drift）？

- B（牙科）倾向 I4：临床任务单位是单牙/病灶；
- A（DL）倾向 I1：当前特征是整图 CLS，先解决漂移和评估；
- **共识**：先 I1 + I2 + I5；I4 放论文 B，等有分割/牙位标注再启动。

### 分歧 2：负结果论文是否可接受？

- D（论文）认为可以，但必须严格、可复现、有机制；
- C（评估）认为当前数据/统计还不够干净，负结果也不可信；
- **共识**：先做 G0 干净重评；如果仍无正向信号，再决定是否写负结果/系统评估。

### 分歧 3：pair cosine 是否能作为主要证据？

- A 认为它是诊断量；
- C 认为不能作为因果证据；
- **共识**：只作辅助诊断，不作为创新点或论文主证据。

### 分歧 4：全参数 vs LoRA

- A 认为全参数 + anti-drift 仍值得一试；
- B/C 认为 LoRA 更安全，尤其 200 张；
- **共识**：先做 LoRA/部分冻结作为保守对照，再决定是否全参数。

## 8. 需要审核人回答的问题（Q1–Q6）
