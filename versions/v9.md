# 版本分析

## 1. 版本定位

v9 的核心目标是在不改变当前项目任何内容的条件下，通过拷贝的方式，将当前项目中已经验证的训练、验证、推理和相关数据整理能力封装为一个可独立使用、可迁移和可复现的发布包。该版本关注工程交付和运行环境隔离，不改变当前单类别 `tooth` 检测任务，也不新增像素级分割、FDI 牙位识别或氟斑牙分级能力。

## 2. 独立包内容

- 在项目根目录下新建专用目录保存 v9 独立包，包内应包含运行所需的源码、命令行入口、依赖配置、必要的配置文件和数据组织说明。
- 训练和预测代码应保持当前 CLI 的主要使用方式，确保独立包能够完成数据校验、数据准备、模型训练、模型验证、单图预测和目录批量预测。
- 数据打包时应区分原始数据、生成数据、测试输入、模型权重和运行输出，避免把临时缓存、测试缓存和无关实验产物误作为发布内容。
- 如果完整数据或模型权重体积过大，应在包内 README 中明确目录要求、准备方式、权重来源和放置路径，不应默认依赖原项目工作区中的隐式相对路径。

## 3. 环境配置要求

目标运行环境具备 128 个 CPU 逻辑处理器、Intel Xeon Gold 6530 处理器、约 1 TiB 内存，以及一张约 96 GiB 显存的 NVIDIA RTX PRO 6000 Blackwell Server Edition GPU。独立包应明确记录 Python 版本、PyTorch、Ultralytics、CUDA 和相关依赖的兼容要求，并提供可重复安装的依赖配置。

训练配置可以利用大显存和多核 CPU，但不应把硬件数量硬编码为唯一可运行条件。应保留设备、batch size、图像尺寸、epoch、AMP 和输出目录等参数的命令行配置，使包也能在较小 GPU 或 CPU 环境中完成验证性运行。

## 4. 包内 README 要求

独立包必须包含自己的 `README.md`，至少说明以下内容：

- 包的任务范围、当前模型能力和明确限制；
- 环境安装、依赖安装和硬件要求；
- 数据目录结构、标注格式以及训练/验证/测试数据的职责；
- 数据校验和数据准备命令；
- 从基础权重训练、从已有 `best.pt` 初始化增量训练的命令；
- 模型验证、单张图像预测和递归目录批量预测命令；
- 输出目录结构、权重位置、预测原图、可视化图、检测 JSON 和牙齿裁剪图的含义；
- 伪标签导出和人工审核注意事项；
- 常见运行问题、设备选择方式和结果复现实验要求。

每条命令都应配有参数解释和输入输出说明，使使用者无需返回主项目查阅其他文档即可完成训练和预测。

## 5. 复现与验收重点

- 独立包安装后应能在包目录内完成导入和 CLI 执行，不依赖原项目的未声明路径或本地开发状态。
- 包内训练和预测应使用明确的相对路径或配置路径，并能指定独立的输出目录，避免覆盖原项目实验结果。
- 应验证包内源码与主项目当前行为一致，尤其是数据格式校验、权重初始化、批量递归推理、预测原图保存和伪标签导出流程。
- 应提供最小化的自动化测试或冒烟验证，至少确认依赖导入、CLI 帮助、数据校验和不加载真实模型的输出保存逻辑能够运行。
- 发布前应清理 `__pycache__`、pytest 临时目录、训练缓存和无关实验结果，并检查 README 中的命令与实际 CLI 参数一致。

## 6. 风险与边界

独立打包容易出现源码、数据、权重和依赖版本不一致的问题。v9 应以当前已验证的检测流程为基线，记录包版本、模型权重、数据清单和运行环境；不要仅复制代码而遗漏数据格式、配置文件或权重加载约束。大规模数据和权重可能使完整包不适合直接复制，因此需要明确哪些内容随包提供、哪些内容由使用者准备。

本版本的验收标准是：根目录下存在结构清晰的独立包；包内 README 能独立指导安装、训练、验证和预测；在目标硬件环境中能够调用当前模型流程；输出结果可追溯且不会覆盖主项目；包内文档明确说明当前是牙齿检测基线，而不是像素级分割或临床诊断系统。
