## 0. 结论先行

1. **审核的核心判断成立**：当前最需要修的是评估有效性与统计口径，而不是马上再训一个 checkpoint。
2. **但审核中的一部分问题属于检测范围**（八模型 AP 口径、OMNI 检测 test 泄漏）；既然本轮只做 DINOv3 预训练，这两项标记为“延后”，不作为当前阻断项。
3. **当前两个分类 probe 与 42,618 张预训练图哈希重叠为 0**：`dental_fluorosis` 200 张和口腔疾病 720 张都没有进入预训练集，因此分类 probe 本身不是 transductive 泄漏。
4. **真正需要先修的是分类评估集内部重复与标签冲突**：
   - 口腔疾病 720 张：643 个唯一哈希，40 个重复组，77 个额外副本，22 组跨 Calculus/Gingivitis；
   - 氟斑牙 200 张：199 个唯一哈希，1 组同类重复。
5. **在这些问题修完之前，Stage 1 的所有 probe 数字只能算“初步观察”**，不能作为“域内预训练有效/无效”的最终结论，也不能直接写进论文。
6. **预训练策略的改进方向明确**：抑制漂移（base 蒸馏/冻结 Gram）、降低 K/KoLeo、缩短 schedule、数据源平衡与质量、以及 LoRA/部分冻结的保守方案；这些都需要单变量对照，而不是一次性全改。

## 3. 当前 DINOv3 证据（带口径）

### 3.1 Stage 1 训练

- 224/96，batch 320，120 epochs，16,080 steps；
- 峰值 LR 1.21e-4；显存峰值 21.6 GB；
- 最终 checkpoint `ckpt/15999`；
- 最终 DINO local/global 0.345 / 0.263，iBOT 2.352，KoLeo -0.252；
- 训练 loss 健康，无 NaN，梯度未坍缩。

### 3.2 下游 probe（当前口径，待清理）

氟斑牙 4 级（200 张）：

| --- | ---: | ---: | ---: |
| base | **0.799** | **0.798** | **0.916** |
| 5k | 0.744 | 0.740 | 0.847 |
| 10k | 0.767 | 0.764 | 0.872 |
| 15k | 0.780 | 0.778 | 0.886 |
| 16k | 0.779 | 0.777 | 0.884 |

口腔疾病 6 类（720 张）：

| checkpoint | teacher Acc | teacher F1 | teacher QWK |
| --- | ---: | ---: | ---: |
| base | **0.828** | **0.827** | **0.848** |
| 5k | 0.795 | 0.795 | 0.808 |

| 15k | 0.799 | 0.799 | 0.820 |

> 由于疾病集存在跨类重复、氟斑牙有 1 组重复，以上数字目前只能作描述性比较；正式结论要在去重/分组后重算。

### 3.3 符号与统计修正

原报告表格写的是“base − checkpoint”，但实际计算是 `checkpoint − base`：

- 例如 `base − 5k = -0.0689` 实际是 `5k − base`；
- 正确的 `base − 5k` 应为 `+0.0689`；
- **方向结论不变**：trained 仍然低于 base；但标签/符号必须修正。

另外：

- 5 折 × 5 seed 是同一批图上的重复划分，不是 25 个独立实验；
- 不应把 25 折配对 t 检验的 p 值作为正式统计结论；
- 应改为按重复簇/患者/来源分组 CV + cluster bootstrap 置信区间。

### 3.4 数据独立性

- `dental_fluorosis` 200 张：199 唯一哈希，0 个与 42,618 预训练哈希重叠；
- 口腔疾病 720 张：643 唯一哈希，0 个与 42,618 预训练哈希重叠；
- 因此当前两个分类 probe **不是 transductive 泄漏**；
- 但疾病集内部有跨类重复，必须先按哈希/近重复簇分组切分。

## 4. 失败机制：从“已归因”降级为“待验证假设”

当前证据支持：

- Stage 1 的 224 CLS linear probe 在氟斑牙和口腔疾病上都低于 base；
- 5k 的 probe 最差，10k/15k/16k 略好，但仍低于 base；
- pair cosine 从 base 0.823/0.628 降到 5k 0.156/0.074，PR 上升；
- 5k 就已经出现分布变化。

但**不能确定**：

- 是 Sinkhorn/KoLeo/K/N/softmax 中的哪一个造成；
- 是特征“语义结构破坏”还是“线性可分性下降”；
- 是数据源偏置、分辨率、增强、还是全参数漂移；
- 是“训练太久”还是“从早期就偏”。

原因：

- P0 与 Stage 1 同时改了 batch、分辨率、centering、KoLeo、K、训练长度、Gram；
- pair cosine/PR 是分布统计量，不是任务指标；
- 没有单变量对照；
- 疾病集还有重复污染。

因此下一阶段的正确表述是：

> **在当前的 224 CLS linear probe 下，Stage 1 的四个 checkpoint 都没有超过 base；5k 不支持早停；pair cosine/PR 提示特征分布明显变化，但具体原因待单变量消融。**

## 5. 改进方案（只针对 DINOv3 预训练）

### 5.1 先修评估：干净数据 + 正确指标（G0）

这一步不做，后面的预训练实验都无法判断。

1. **疾病 720 去重/分组**
   - 643 唯一哈希、40 重复组、22 组跨类；
   - 方案 A：把跨类重复组改为多标签（Calculus + Gingivitis）；
   - 方案 B：排除跨类冲突组，建立互斥单标签子集；
   - 用哈希/近重复簇做 GroupKFold，避免副本跨 train/test。
2. **氟斑牙 200 去重/分组**
   - 199 唯一哈希，1 组同类重复；
   - 按哈希簇分组切分。
3. **指标**
   - 氟斑牙：QWK（有序）+ MAE / 相邻级准确率 + macro-F1 + 混淆矩阵；
   - 口腔疾病：macro-F1 + balanced accuracy + 每类灵敏度/特异度；**不以 QWK 为主**；
   - 配对：按患者/重复簇 bootstrap 置信区间；不把 25 折 t 检验当正式 p 值。
4. **重跑已有 checkpoint**
   - base、5k、10k、15k、16k 全部在同一干净协议下重跑；
   - 报告差值方向、效应量、CI；修正符号。

### 5.2 预训练策略改进

#### A. 抑制漂移（最高优先级）

目标：让 backbone 在适应牙科域的同时，不丢掉 base 的语义结构。

1. **base 特征蒸馏**
   - 对 CLS 和 patch token 加 `cosine/MSE(student_feat, base_feat)`；
   - 权重 0.1–0.5，可 warmup；
   - 这是最直接的 anti-drift 正则。
2. **冻结 Gram anchor**
   - 当前 `gram.ema_teacher: true` 的 Gram teacher 是 live EMA，基本空转；
   - 改为 `ema_teacher: false` + `ckpt=base DINOv3` + `rep_update: false`；
   - 约束 patch 特征不要偏离 base；适合高分辨率/dense 阶段。
3. **LoRA / 部分冻结预训练**
   - 冻结 backbone，只训练 LoRA 旁路 + DINO/iBOT head；
   - 作为保守对照，验证“少量适配能否保留 base 特征”；
   - 如果 LoRA 预训练能接近 base，说明全参数漂移是主因。

#### B. 降低记忆/过度分散风险

1. **K 从 32768 降到 8192/16384**
   - K/N 从 0.77 降到 0.19/0.38；
   - 降低 prototype 记忆，可能缓解过度分散。
2. **KoLeo 从 0.05 降到 0.01–0.02**
   - 当前特征已经过度分散，继续推远没有意义；
   - 如果有 base 蒸馏，KoLeo 可以更低甚至关闭。
3. **teacher momentum 0.992 → 0.996–0.999**
   - 更稳定的 teacher 目标，减少学生追噪声。
4. **layerwise decay 0.9 → 0.8–0.85**
   - 下层更稳，减少整体漂移。

#### C. 训练 schedule

1. **缩短到 30–60 epochs（约 5k–10k steps）**
   - 当前 120 epochs 后段平台，且漂移从 5k 就发生；
   - 短 schedule + early probe 更可控。
2. **峰值 LR 从 1.21e-4 降到 5e-5–8e-5**
   - 减小对 base 的冲击；
   - 配合 anti-drift 正则，避免“只是学得慢”。
3. **每 1k–2k 保存 checkpoint，probe 后选最佳**
   - 不要用 final；不要用 training loss 选模型。

#### D. 数据策略

1. **来源平衡**
   - COde 87% → 设上限或降采样；
   - 提高 AlphaDent / 高分辨率图权重；
   - 避免模型学“来源/背景”而不是牙齿结构。
2. **质量筛选**
   - 过滤短边过小、模糊、过曝/黑屏、无牙图；
   - 97.3% 短边 <384，224 训练可以，但 512 阶段要分层。
3. **自适应 crop 比例**
   - 小图（短边 <384）：scale 0.4–1.0，避免裁太小再放大；
   - 中图：0.32–1.0；
   - 大图：0.1–0.5，保留细节；
   - 输出仍固定 224，避免同 batch 变尺寸。
4. **增加与下游接近的数据**
   - 如果有更多高分辨率口内临床图/氟斑牙图，优先加入；
   - 但必须与评测集去重、无标签泄漏。

#### E. 分辨率与 dense 证据

1. **先做 224/384/512 的 CLS + patch-mean probe**
   - 不训练，只提取特征；
   - 看高分辨率是否改善；
2. **再做 patch/ROI/dense 小实验**
   - 氟斑牙可能依赖局部釉质纹理；
   - CLS 线性 probe 不能代表 dense 特征；
3. **Stage 2 只在有正向证据时跑**
   - 512/128 + Gram anchor；
   - 与“224 继续训练”同预算对照。

## 6. 建议的实验矩阵

所有实验：同一干净数据、同一 probe 协议、单变量改动、每 1k–2k 步 probe。

| ID | 变量 | 目的 | 预计步数 |
| --- | --- | --- | ---: |
| E0 | 当前 recipe + 干净数据重评 | 建立可信基线 | 0（只重跑 probe） |
| E1 | 短 schedule（40 epochs）+ 低 LR | 验证“少训但更稳” | ~5,300 |
| E2 | E1 + K=16384 | 降低 prototype 记忆 | ~5,300 |
| E3 | E2 + KoLeo=0.02 | 缓解过度分散 | ~5,300 |
| E4 | E3 + base 特征蒸馏（0.2） | 抑制漂移 | ~5,300 |
| E5 | E4 + 冻结 Gram anchor | 约束 patch 特征 | ~5,300 |
| E6 | E5 + 数据源平衡/质量过滤 | 处理数据偏置 | ~5,300 |
| E7 | LoRA / 部分冻结 SSL | 保守域适配对照 | ~5,300 |
| E8 | 512/128 Stage 2 + Gram anchor | 高分辨率适应 | ~3,000 |

Gate：

- 每个实验在 2k/5k/8k/10k probe；
- 只有在干净数据上，至少一个任务相对 base 有稳定正增益（分组 CI 不跨 0），才进入下一阶段；
- 如果 E1–E7 全部不如 base，停止全参数预训练，转 base + LoRA/下游适配，或把论文改为负结果/系统评估。

## 7. 建议的第一轮配置（仅作起点，需消融）

```yaml
# 224/96, batch 320, 40 epochs ≈ 5,360 steps
train:
  batch_size_per_gpu: 320
  OFFICIAL_EPOCH_LENGTH: 134
  centering: "softmax"

dino:
  head_n_prototypes: 16384
  koleo_loss_weight: 0.02

teacher:
  momentum_teacher: 0.996
  final_momentum_teacher: 1.0

optim:
  epochs: 40
  lr: 0.00004          # 峰值约 8.9e-5（sqrt_wrt_1024, batch 320）
  warmup_epochs: 3
  layerwise_decay: 0.85
  freeze_last_layer_epochs: 1

gram:
  use_loss: false      # 第一轮先关闭；第二轮换冻结 anchor
```

建议新增（需要代码改动）：

- `base_feature_distill_weight: 0.2`，对 CLS + patch token 做 cosine 蒸馏；
- 每 1000 步保存，`keep_every: 2000`；
- 训练脚本每隔 1k–2k 自动跑一次干净 probe（或导出 backbone 后离线 probe）。

> 这不是“已验证配方”，而是第一轮受控实验的起点；必须与 E0 基线、单变量对照一起看。

## 9. 对论文与项目的影响

- 当前论文 A 的核心假设“域内预训练提升下游”**尚未被支持**；
- 但审核也指出：高分辨率、patch/dense、同预算微调尚未评估，不能据此断言域适配无效；
- 本轮改进的重点是：
  1. 用干净数据和正确指标重算；
  2. 用 anti-drift 正则/短 schedule/数据平衡做受控预训练；
  3. 用 LoRA/全量、dense/patch 任务判断 backbone 是否还有价值；
- 如果最终仍无正向信号：
  - 论文可改为“口内摄影表征适配的严格评估/负结果分析”；
  - 或把主方法改为 base + LoRA/检测；
  - 不建议用训练 loss 或非标准 AP 支撑主张。
