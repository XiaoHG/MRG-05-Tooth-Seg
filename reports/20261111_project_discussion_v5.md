## 0. 结论摘要

1. **接受 v4 的核心修正**：v3 把“漂移机制”提升为论文主线、把 I1 评为中高新颖性/高可行性，这一步跳得过快。
2. **论文主故事改为路径 B（受控评估）**：
   - 主问题：在患者/来源隔离、标签语义清晰、同计算与同下游预算下，口内域继续预训练何时优于直接用 DINOv3 base？
   - 路径 A（方法论文）作为条件分支；路径 C（临床应用）暂不作为主稿。
3. **创新点降级**：
   - I2（数据协议）+ I5（局部评估）是当前最可交付的贡献；
   - I1（base-anchored adaptation）暂定为“候选配方/工程组合”，只有相对固定 base 蒸馏、官方 Gram、LoRA 等简单基线显示特有增益后，才升级为方法创新；
   - I3 弱；I4 独立规划，不预先称高新。
4. **暂不承诺 3–4 个新训练**：先完成数据/评估清理与多读出重评，再做资源冒烟，最后批准 R0 + 1–2 个单变量试验。
5. **暂不定 venue/时间线**：先做可发表性检查，再逆推时间表。
6. **必须优先确认的三件事**：任务单位（整图/单牙/患者）、标签语义（氟斑牙分级标准、六病是否共病）、患者/近重复隔离测试集。

## 2. 修正后的项目判断

### 2.1 已完成、可支撑的部分

- 官方 DINOv3 ViT-B/16 域内 Stage 1 已训练 16,080 步；
- 有 5k/10k/15k/16k checkpoint 和同协议 base probe；
- 多源数据审计/去重/离线训练/评估链路可跑通；
- 这些可以支撑“实验平台与初步观察”，不能支撑“方法有效”。

### 2.2 仍是研究空白、需要先解决的部分

1. **任务单位不清**：氟斑牙四级是整图、单牙还是患者级？原始分级标准是什么？
2. **标签语义不清**：六类口腔疾病是否互斥？跨类重复是共病还是错标？是否应改多标签？
3. **数据独立性不足**：字节去重不等于语义/患者去重；需要近重复、患者、来源审计。
4. **评估太窄**：只有整图 CLS 线性 probe；缺少 ROI/patch、LoRA/全量、分辨率分层。
5. **训练归因不足**：P0/Stage 1 多因素同时变化；没有同预算基线。
6. **资源未核验**：Gram anchor、512 Stage 2 的真实显存/速度未测。

### 2.3 修正后的项目定位

> 当前项目应定位为“小规模、来源不平衡的口内图像继续预训练研究平台”，主问题是“何时、对什么任务、在什么评估条件下，域内预训练优于 base”，而不是“我们已经证明 OralDINO 有效”。

## 3. 修正后的架构判断

### 3.1 保留的部分

- **ViT-B/16 主干保留**：86M、RoPE、4 storage tokens、dense patch 特征，适合后续检测/分割/分级；
- **师生 EMA + 多裁剪 + iBOT**：合理起点；
- **224/96 主训练 + 可能的 512/128 适应**：方向合理，但需资源核验。

### 3.2 需要修正的部分

1. **不要把“全参数危险”直接推出“必须 anti-drift”**
   - 真正的问题是：需要保留哪些通用不变性，又需要获得哪些牙科局部信号？
   - 只约束接近 base 可能保护 CLS probe，却限制新的局部表征；
   - 必须同时测整图、ROI、patch；不能只用 CLS。

2. **I1 的组件都是已有思想**
   - 固定 base 蒸馏、官方 Gram anchoring、LoRA/部分冻结均为已有；
   - 组合本身不足以构成方法创新；
   - 若要有新意，需要**牙科特定的锚定目标**，例如：
     - 用检测 ROI 约束 student/teacher 在牙齿区域的一致性；
     - 用牙弓/牙位结构约束 patch token；
     - 但这需要 ROI/牙位标签，当前不具备，只能作为候选。

3. **Gram anchor 不是改三个字段**
   - 当前配置 `gram.use_loss: false`、`img_level: false`、`gram_teacher_crops_size: null`；
   - 只有 `use_loss: true` 才构建 Gram teacher；独立 teacher 需要 `gram_teacher_crops_size`；
   - `img_level: false` 时 Gram 矩阵按 `[B×P, B×P]` 计算；224/16、B=320 时边长约 62,720，fp32 约 15.7 GB，单矩阵就接近 25GB 预算的一大半；
   - 必须先做 `img_level: true`/分块/小 batch 的显存冒烟，不能直接排进正式实验。

4. **三类 LoRA 要分开**
   - base 的下游监督 LoRA；
   - OralDINO 的下游监督 LoRA；
   - SSL 阶段的 LoRA continue-pretraining。
   - 前两者检验下游可适配性；第三者才是新的预训练方案。不能混为一谈。

> **在患者/来源隔离、标签语义清晰、同计算与同下游预算的条件下，口内域继续预训练何时优于直接使用 DINOv3 base？**

这是一个可证伪问题，不预设正向或负向结果。

### 4.2 路径选择

| 路径 | 内容 | 当前判断 |
| --- | --- | --- |

## 5. 修正后的创新点评估

| 编号 | 创新点 | 修正后新颖性 | 可行性 | 当前角色 |
| --- | --- | --- | --- | --- |
| I1 | base-anchored dental DINOv3 adaptation | **低到中**（组合已有蒸馏/Gram/LoRA；需牙科特定锚定才可能升级） | 中（Gram 资源风险；蒸馏需实现） | 候选配方；暂不作主创新 |
| I2 | data-centric dental SSL protocol | **中**（协议/资源贡献；仅 SHA 去重不够） | 高（可先做） | 当前最可交付 |
| I3 | small-batch softmax+center、K/N 校准 | **弱**（softmax centering 非新；K/N 非记忆律） | 高 | 实现细节/消融 |
| I4 | 单牙 token / 牙间 Transformer | **潜在高，但需文献/对照** | 低到中（缺 mask/牙位标签） | 论文 B，独立规划 |
| I5 | ROI/patch 评估 | **中**（评估贡献，不是独立方法） | 高（有 ROI 框即可） | 当前最可交付之一 |

### 推荐组合

- **当前交付**：I2 + I5（数据协议 + 局部评估），先把“可信评估”做出来；
- **条件升级**：I1 只有在相对“固定 base 蒸馏 / 官方 Gram / 下游 LoRA / 数据平衡”显示特有增益后，才升级为主创新；
- **独立规划**：I4 单牙 token/牙间 Transformer，需牙位/病灶标签，不与当前论文混写；
- **I3** 作为实现细节，不作为主创新。

### 牙科医学价值

- 氟斑牙分级可能按 Dean 指数、TF 指数或项目自定义四级体系，三者不能默认互换；必须找回原始标注说明和牙医审核记录；
- 牙石、牙龈炎等共病使单标签六分类可能从任务定义就不适合；应先决定多标签诊断、主病种分类，还是仅做图像类别识别；
- **任务定义是本项目最大的研究设计创新机会，也是最大的有效性风险。**

## 6. 对 D1–D4 的回应

### D1 任务单位

**当前事实**：

- `dental_fluorosis` 是 4 级目录（normal/mild/moderate/severe），50 张/类；没有患者 ID、牙位、单牙 ROI 标签；
- 口腔疾病 6 类是整图目录，跨类重复可能反映共病或错标；
- 目前只能做整图分类，不能声称单牙/患者级。

**我们的回应**：

1. 先向数据所有者确认：
   - 氟斑牙原始分级标准（Dean/TF/自定义）；
   - 是否有患者 ID、牙位、单牙 ROI；
   - 六类疾病是否允许共病，跨类重复的原图来源。
2. 在确认前，论文只写“整图 4 级/6 类图像分类”，不写“单牙分级/患者级筛查”。
3. 如果患者 ID 不可得：
   - 用来源/近重复簇做分组切分；
   - 明确写“图像级结论，不能外推到患者级”；
   - 不声称临床泛化。

### D2 方法新意

**我们的回应**：

- 接受审核人判断：I1 目前是“固定 base 蒸馏 + 官方 Gram + 数据平衡 + 短 schedule”的组合，**低到中新颖性**；
- 若要升级为方法创新，需要牙科特定机制，候选方向：
  1. **ROI-aware anchor**：用检测器 ROI 约束 student/teacher 在牙齿区域的一致性，而不是整图 CLS；
  2. **arch-aware token**：牙弓/牙位结构约束 patch token；
  3. 但这些需要 ROI/牙位标签，当前不具备，只能作为论文 B/后续工作；
- 当前论文以 I2+I5 为主，I1 作为候选配方/消融，不预设为正方法。

**最强简单对照**（若做 I1）：

1. 固定 base 特征蒸馏（无 Gram、无数据平衡）；
2. 官方 Gram-only（或 Gram + 无蒸馏）；
3. 下游 LoRA/线性头；
4. 数据平衡但不加蒸馏/Gram。

只有在这些对照之上仍有特有增益，才值得称方法创新。

### D3 最小证据

**当前证据**：

- 两个分类集与 42,618 预训练图**字节级哈希重叠 0**；
- 但未做感知哈希/embedding 近邻/患者/来源审计；
- 疾病集有 22 组跨类重复；氟斑牙 1 组同类重复。

**我们的回应**：

1. 先做近重复/感知哈希/embedding 检索，补患者/来源审计；
2. 用来源/近重复簇做分组切分；能拿到患者 ID 则患者级分组；
3. 锁定一个独立测试集（来源/患者/近重复簇与 SSL 隔离），只做最后一次评估；
4. 如果无法获得患者 ID 或独立测试：
   - 论文降级为“图像级、来源受限”的受控评估；
   - 不写患者泛化/临床效用；
5. 近重复/患者审计完成前，措辞改为“与已比对清单无字节级重叠，仍待审计”。

### D4 资源和排期

**我们的回应**：

- Gram anchor 不是改三个字段；当前 `use_loss: false`、`img_level: false`、`gram_teacher_crops_size: null`；需先实现/配置/显存冒烟；
- 224/batch 320、`img_level: false` 时 Gram 矩阵约 62,720²，fp32 约 15.7GB，风险高；先试 `img_level: true`/分块/小 batch；
- 512 Stage 2 也未验证显存/速度；
- 因此**不按固定周数排 3–4 个训练**，改为：
  1. 第 1 周：数据/评估清理 + 多读出重评（CLS/patch/ROI）；
  2. 第 2 周：Gram/512 资源冒烟 + R0 同预算基线；
  3. 根据误差分析，批准 1–2 个单变量试验（R1/R2/…）；
  4. 再决定 Path A/B/C 和 venue。
