# 版本安排
- 源码放在 `src/` 目录下，demo 文件放在 `cli/` 目录下，测试代码放在 `tests/` 目录下
- v5版本实现了基础的yolo11训练工作，并进行了dataset 的test目录下面的预测工作；
- v6的任务是要将test的预测结果output/predict/ 下面的预测结果的confidence >= 0.9的结果作为训练样本进行再次的去训练模型；
- 所以这个版本是将predict的目录下面的所有的预测结果的大于等于0.9的结果抽取出来，同时把原图也拿到，加入到dataset/raw目录下面；
- 加入到raw目录下面新增一个子文件夹进行保持，要参照现有的文件目录进行保存，例如fluorosis目录的结构和内容，保证后续能够无缝的添加到训练样本中；
- 本版本不用改动训练和预测代码，只需要将predict的预测结果文件转换到dataset/raw的内容即可；
- 并将新添加到raw的内容，同样的添加到现在训练集和测试集中，新添加数据之后要做好训练集和测试集的划分；

## 版本分析

### 1. 版本定位

v6 是在 v5 单类牙齿检测模型基础上的伪标签（pseudo-label）数据增量版本：从 `output/predict/` 的预测结果中筛选高置信度检测框，将对应的原始口腔图像和 YOLO 标签整理为新的 `dataset/raw/` 数据来源，再参与下一轮训练。该版本不涉及 FDI 牙位识别、氟斑牙分级或像素级分割，当前可训练目标仍是单类 `tooth` 检测。

### 2. 当前数据与预测结果盘点

当前 `dataset/raw/` 中已有两份带标注检测数据：`fluorosis` 为 22 张图像、22 个标签文件、335 个牙齿框；`OMNI_COCO-seg-train` 为 119 张图像、119 个标签文件、1714 个牙齿框。当前训练集和验证集分别为 113 张与 28 张，另有 60 张未标注图像位于 `dataset/images/test/`。

`output/predict/` 中存在与这 60 张 test 图像一一对应的 60 个 `*_detections.json` 文件。每个检测结果包含原图上的像素坐标 `box_xyxy` 和 `confidence`；当前共有 501 个置信度不低于 0.9 的候选框，59 张图像至少包含一个此类候选框。

### 3. 可行性与核心风险

将高置信预测转换为 YOLO 标签在技术上可行：读取原图宽高后，将像素坐标 `xyxy` 转为 `class x_center y_center width height` 的归一化五列标签即可。但“单个框置信度不低于 0.9”不能证明该图中其他可见牙齿已被完整检出。

当前 59 张候选图像同时存在高、低置信度框。若仅把高置信框写入标签，同图中未写入的真实牙齿会在 YOLO 训练中被当作背景，模型可能进一步降低对这些牙齿的召回率。因此不能把所有高置信框直接视为可用训练真值。

此外，伪标签由当前教师模型生成，再用于训练同类学生模型，存在确认偏差：原模型的漏检、误检和边界偏差可能被放大。test 图像原本没有人工标签，不能用于计算真实检测指标，也不能因其已有伪标签而被视为独立测试集。

### 4. 新增 raw 数据规范

建议新建 `dataset/raw/pseudo-label-v6/`，保持现有 raw 来源的结构：

```text
pseudo-label-v6/
  images/
  labels/
  classes.txt
  notes.json
```

其中 `images/` 必须保存预测所对应的完整原图，不能以单颗牙 crop 替代；`labels/` 中每张入选图像有同名 `.txt` 标签；`classes.txt` 保持单行 `tooth`。每个框按原图尺寸归一化为 `0 x_center y_center width height`，并在写入前裁剪到图像范围、过滤零面积或非法框。

`notes.json` 或独立 manifest 应逐图记录来源图像名、原图 hash、来源检测 JSON、教师权重路径、推理阈值、筛选阈值、生成时间、候选框数量和人工审核状态。这样可追溯每条伪标签，并在效果变差时精确移除该来源而不影响已有 raw 数据。

### 5. 候选筛选与人工审核

建议将 `confidence >= 0.9` 仅作为候选导出阈值，而不是最终入库条件。转换时先生成候选目录和审核清单，再由人工叠加查看检测框与原图。只有满足“框位置合理、没有明显漏牙、没有明显误检、可见牙齿覆盖完整”的图像才进入 `pseudo-label-v6`。

若人工审核资源有限，可增加图级完整性规则作为预筛选，例如：图中所有候选牙均达到较低置信度阈值、牙齿数量与排列明显合理、没有孤立异常框；但该规则只能减少审核量，不能替代人工确认。发现一张图有明显漏牙时，应整张图排除，而不是只保留其中的高置信框。

### 6. 训练集与验证集划分原则

伪标签只能加入训练集，不能进入验证集。现有 `prepare_raw_yolo_dataset()` 会合并所有 raw 子目录后按来源随机划分 train/val；若直接新增 `pseudo-label-v6` 后执行当前流程，伪标签会随机进入 val，使验证指标混入模型自身生成的标签，失去可信度。

因此，v6 数据整理完成后应冻结当前 28 张人工标注验证图像及其标签，仅将审核通过的伪标签图像追加到 train。若后续实现重建脚本，需要显式支持“固定 val、伪标签仅训练”的划分规则；在此之前，不应执行会把伪标签切入 val 的全量随机重划分。

### 7. 实施流程

1. 读取 `output/predict/` 的检测 JSON，筛选置信度不低于 0.9 的候选框，并定位对应 test 原图。
2. 按原图尺寸转换候选框为 YOLO 格式，生成候选图像、标签和 manifest；此阶段不改动既有 raw 来源。
3. 对候选图像进行叠加可视化与逐图审核，记录通过、拒绝及原因；有明显漏检或误检的图像整体拒绝。
4. 将审核通过的完整原图和标签放入 `dataset/raw/pseudo-label-v6/`，写入 `classes.txt` 与可追溯的 `notes.json`。
5. 保持既有人工标注 val 不变，只把通过审核的新增样本加入 train，完成图像与标签一一对应检查后训练。
6. 使用同一份人工真值验证集，比较引入伪标签前后的 precision、recall、mAP50 和 mAP50-95，并保留每轮权重与数据 manifest。

### 8. 验收与回滚标准

转换完成后应确认：新增图像与标签文件一一对应；所有标签均为合法五列数值，类别均为 0，坐标在 0 到 1 范围内且宽高大于 0；抽样可视化后的框与牙齿位置一致；原有 raw 数据未被修改；每张新增图像都有审核记录。

训练效果只能在固定的人工标注验证集上判定。若新增伪标签后 recall、mAP 或错误案例表现下降，应依据 manifest 将 `pseudo-label-v6` 从训练来源中移除并回滚到 v5 数据集，而不是继续叠加未经验证的伪标签。
