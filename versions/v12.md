# 版本分析

## 总体目标

本版本的核心目标是扩展现有模型对比实验范围，并验证不同检测模型在 OMNI_COCO 数据集上的表现。当前项目已经能够通过 `--weights` 选择已有模型权重，因此后续实验应以统一的预测和评估流程加载不同模型，避免因调用方式不同引入额外差异。

## 模型对比范围

计划纳入 Faster R-CNN、RetinaNet、YOLOv8m、YOLO26m、RT-DETRv2-L 和 RF-DETR-M。模型类型覆盖两阶段检测器、经典单阶段检测器、YOLO 系列和 Transformer/实时检测器，有助于比较不同检测范式在牙齿目标检测任务中的适应性。RF-DETR-M 为新增模型，需要额外确认其权重格式、推理接口、类别配置和训练依赖是否能够接入当前项目流程。

## 数据与实验设计

实验数据以 `dataset/OMNI_COCO` 下的 `before` 和 `after` 目录为准。两者目录结构一致，主要差异在于标注细致程度，因此实验应保持训练/验证划分、输入尺寸、训练轮数、随机种子、评价阈值和后处理设置一致，仅改变模型或数据版本。

由于 `before` 与 `after` 的标注精细度不同，二者之间的指标差异不能简单解释为模型能力变化。对比时应分别进行同版本内部的模型排名，再分析同一模型在 `before` 与 `after` 之间的变化；必要时检查标注框数量、框位置和边界质量，避免把标注差异误判为泛化能力差异。

## 建议记录的结果

每个模型和数据版本至少应保留模型名称、权重来源、数据版本、训练参数、Git 提交版本、最佳 epoch、Precision、Recall、mAP50、mAP50-95、训练耗时、`best.pt` 和 `last.pt`。模型比较应优先使用固定验证集，最终确认后再使用独立 test 集，不能用无标签或未经审核的伪标签作为测试真值。

## 风险与验收重点

Faster R-CNN、RetinaNet、RT-DETRv2-L 和 RF-DETR-M 未必与当前 Ultralytics 单一训练入口完全兼容，需要先完成 1 个 epoch 的冒烟测试，确认模型能正确读取单类别 `tooth` 数据、生成验证结果并保存权重。所有模型应使用相同的输出命名和目录结构，避免实验产物相互覆盖。

本版本完成的判定标准是：新增模型均能完成可复现训练和验证；`before/after` 两个数据版本均有完整实验产物；指标和资源消耗可以横向比较；对于标注精度差异、模型接口差异和未完成的模型适配均有明确记录。当前版本说明本身只提出实验规划，不能据此声称任何模型已经取得性能优势或已实现像素级牙齿分割、牙位识别和临床分级。
