# 版本分析

## 1. 数据集现状

- 当前需要分析的主数据位于 `dataset/OMNI_COCO/`，包含 `before` 和 `after` 两个版本；两者均采用 `train/`、`val/`、`test/` 存放图像，采用 `labels/train/`、`labels/val/`、`labels/test/` 存放 YOLO 标签。
- `after` 的训练集为 2481 张图像、验证集为 857 张图像，训练图像与标签按文件 stem 一一对应。
- `before` 的有效训练数据同样为 2481 对图像/标签。
- 两个版本的 `test` 目录均有对应的 `labels/test/`，可以在训练和模型选择完成后用于最终 precision、recall、mAP 评估；不应在调参阶段反复使用 test 指标。
- 当前 `data.yaml`、清单和 Kaggle 启动器需要以实际传入的数据根目录为准，不能假设数据一定位于仓库内的 `dataset/` 或存在 `dataset/raw/`。

## 2. 当前实现与问题

- 项目目前默认使用 `yolo11n.pt`，训练函数支持通过 `--weights` 传入预训练权重或上一轮权重，但 CLI 没有独立的 `--model` 参数。因此“通过命令行指定模型”目前只能通过不同的权重文件间接实现，不利于批量、可复现的基线对比。
- `weights/` 中已有 `yolo11n.pt` 和训练过程中产生的 AMP 检查权重；新增模型应明确记录模型名称、来源 URL/版本和文件校验值，避免把不同模型的权重混在同一目录而无法追溯。
- 训练输出应按“数据版本 + 模型名称 + 实验编号”区分，例如 `output/train/omni-coco-before/yolo11n/`、`output/train/omni-coco-after/yolo11s/`，不要让不同模型共享同一个 Ultralytics 实验目录。
- `kaggle_train/train.py` 已能识别当前 `before`/`after` 的目录布局，并将其复制为标准 `images/`、`labels/` 视图；后续增加模型对比参数时，必须保留这一数据路径自适配逻辑。

## 3. 建议的基线模型

基线不应全部来自 YOLO 系列。建议选择能够代表不同检测范式的 5 个模型：

1. `YOLO11n`：当前基线，参数量和速度最低，用于保持历史结果可比性。
2. `YOLO11s`：同系列更大模型，用于衡量模型容量增加带来的精度收益。
3. `Faster R-CNN R50-FPN`：两阶段 CNN 检测器，使用 ResNet-50/FPN 提取特征，作为经典高精度边界框检测基线；当前 YOLO 框标注可以直接转换使用。
4. `DETR-R50` 或 `Deformable DETR`：Transformer 检测器，用于比较集合预测和注意力机制与 YOLO/CNN 检测器的差异；Deformable DETR 对小目标和收敛速度通常更友好。
5. `RT-DETR-R18/R50`：实时 Transformer 检测器，作为速度与精度兼顾的非 YOLO 基线；应根据 GPU 显存选择 R18 或 R50，而不是默认使用大模型。

`Mask R-CNN` 可以作为扩展架构，但不能直接作为当前数据的严格基线：它的标准检测头之外还需要实例分割 mask，而当前数据只有 YOLO 边界框。若暂时没有像素级掩码，可以只比较其 box 分支，但这会关闭或弱化 mask 分支，不能称为完整的 Mask R-CNN 分割实验；不应把矩形框自动填充成牙齿 mask 并宣称获得了真实分割监督。待补充人工多边形/掩码标注后，再将 `Mask R-CNN R50-FPN` 纳入分割对比。

所有检测模型必须使用同一份训练/验证清单、相同输入尺寸、训练轮数、随机种子和评估流程。两阶段模型与 Transformer 模型的 batch、学习率和训练轮数可以因架构需要调整，但必须在实验记录中明确说明，不能把不同训练预算下的结果直接并列为公平结论。

## 4. 实验设计

- 每个模型分别在 `before` 和 `after` 数据版本上训练，形成成对实验；模型、数据版本和实验编号写入输出目录及实验记录。
- 首轮对比建议固定 `imgsz=1024`、`epochs=50`、AMP 设置和 GPU 类型；显存不足时统一降低输入尺寸或 batch，不能只对某一个模型单独放宽条件。
- 每个实验至少保存 `args.yaml`、`results.csv`、`best.pt`、`last.pt`、验证指标和 Git commit。比较指标包括 precision、recall、mAP50、mAP50-95、训练耗时和推理速度。
- 应同时记录数据集版本、训练/验证样本数、标签数量、模型预训练权重来源及哈希。不要把无标签 `test` 图像的可视化结果当作定量性能证明。
- 训练前先执行数据结构检查，确认图像和标签 stem 集合一致，并排除快捷方式、压缩包和其他非图像文件；训练后再检查 Ultralytics 扫描日志，确保没有出现 `backgrounds` 或 `No labels found`。

## 5. v11 执行顺序

1. 清理或隔离 `before/train/` 中的快捷方式等非数据文件，重新生成并核对两个数据版本的清单。
2. 为 CLI 增加显式模型/架构参数，例如 `--model yolo11n.pt`、`--model fasterrcnn_resnet50_fpn` 或 `--model detr_r50`，同时保留 `--weights` 作为初始化权重参数；不同框架的模型适配器应统一数据和评估接口。
3. 将各架构的公开预训练权重放入 `weights/`，按模型和框架分目录保存，并记录版本、来源 URL、许可证和哈希。
4. 更新 `kaggle_train/train.py`，透传模型参数、数据版本和输出名称；先进行 1 epoch 冒烟测试，再启动正式 50 epoch 实验。
5. 按模型和数据版本分别保存输出，先完成 YOLO、Faster R-CNN、DETR/Deformable DETR 和 RT-DETR 的检测对比；完成 mask 标注后再运行 Mask R-CNN 分割扩展实验。
